Configuration options for the Live API

Preview: Using the Firebase AI Logic SDKs with the Gemini Live API is a feature that's in Preview, which means that it isn't subject to any SLA or deprecation policy and could change in backwards-incompatible ways.


Even with the basic implementation for the Live API, you can build engaging and powerful interactions for your users. You can optionally customize the experience even more by using the following configuration options:

  • Response voice and language

  • Transcriptions for audio input and output

  • Voice activity detection (VAD) (for example, to handle interruptions)

  • Session management

Note: Firebase AI Logic does not yet support the following when using the Live API (but they're coming soon!):
Adding a thinking configuration or setting the input media resolution.

Transcriptions for audio input and output

Click your Gemini API provider to view provider-specific content and code on this page.

As part of the model's response, you can receive transcriptions of the audio input and the model's audio response. You set this configuration as part of the model configuration.

  • For transcription of the audio input, add inputAudioTranscription.

  • For transcription of the model's audio response, add outputAudioTranscription.

Note the following:

  • You can configure the model to return transcriptions of both input and output (as shown in the following example), or you can configure it to return only one or the other.

  • The transcripts are streamed along with the audio, so it's best to collect them like you do text parts with each turn.

  • The transcription language is inferred from the audio input and the model's audio response.

Swift

// ...

let liveModel = FirebaseAI.firebaseAI(backend: .googleAI()).liveModel(
  modelName: "GEMINI_LIVE_API_MODEL_NAME",
  // Configure the model to return transcriptions of the audio input and output.
  generationConfig: LiveGenerationConfig(
    responseModalities: [.audio],
    inputAudioTranscription: AudioTranscriptionConfig(),
    outputAudioTranscription: AudioTranscriptionConfig()
  )
)

var inputTranscript: String = ""
var outputTranscript: String = ""

do {
  let session = try await liveModel.connect()
  for try await response in session.responses {
    if case let .content(content) = response.payload {
      if let inputText = content.inputAudioTranscription?.text {
        // Handle transcription text of the audio input.
        inputTranscript += inputText
      }

      if let outputText = content.outputAudioTranscription?.text {
        // Handle transcription text of the audio output.
        outputTranscript += outputText
      }

      if content.isTurnComplete {
        // Log the transcripts after the current turn is complete.
        print("Input audio: \(inputTranscript)")
        print("Output audio: \(outputTranscript)")

        // Reset the transcripts for the next turn.
        inputTranscript = ""
        outputTranscript = ""
      }
    }
  }


} catch {
  // Handle error
}

// ...

Voice activity detection (VAD)

Voice activity detection (VAD) lets the model recognize when a person is speaking. This is essential for creating natural conversations, as it lets you interrupt the model at any time. VAD is enabled by default.

You can customize the behavior of VAD, including handling interruptions. You can alternatively disable automatic VAD to take complete manual control over conversational turns (such as for a push-to-talk interface).

Configure voice activity detection (VAD)

Click your Gemini API provider to view provider-specific content and code on this page.

The following example shows how you can customize the behavior of VAD by setting realtimeInputConfig as part of the model configuration. Learn about available settings for this configuration in the table later in this section.

Swift

// ...

let liveModel = FirebaseAI.firebaseAI(backend: .googleAI()).liveModel(
  modelName: "GEMINI_LIVE_API_MODEL_NAME",
  generationConfig: LiveGenerationConfig(
    responseModalities: [.audio],
    // Configure voice activity detection (VAD), interruption handling, and turn coverage.
    // IMPORTANT: Example values shown here. Make sure to update for your use case.
    realtimeInputConfig: RealtimeInputConfig(
      automaticActivityDetection: ActivityDetectionConfig(
        startSensitivity: .low,
        endSensitivity: .low,
        prefixPadding: .milliseconds(20),
        silenceDuration: .milliseconds(500)
      ),
      activityHandling: .interrupt,
      turnCoverage: .onlyActivity
    )
  )
)

Kotlin (Android)

// ...

Available VAD configuration settings

Setting Supported values Description
Automatic activity detection (automaticActivityDetection)
startSensitivity
  • LOW (default)
  • HIGH

Determines how readily the server detects when a user begins speaking:

  • LOW: Less sensitive to faint sounds. This helps to prevent ambient noise from inadvertently starting a speech turn.
  • HIGH: More sensitive. This helps to quickly detect quieter speech or soft-spoken words.
endSensitivity
  • LOW (default)
  • HIGH

Determines how readily the server detects when a user stops speaking:

  • LOW: Less sensitive to trailing pauses. The server accommodates natural hesitations or quieter words at the end of a sentence.
  • HIGH: More sensitive. The server concludes the speech turn promptly once voice levels drop.
prefixPadding Duration in milliseconds
(default: None (0 ms))

Defines the amount of audio to include before speech is detected.

This "look-back" buffer ensures the model captures the full onset of speech, including the first syllable which often starts before the detector triggers.

  • The default value of 0 can cause the beginning of words to be clipped.
  • Recommended: 20-50 milliseconds
silenceDuration Duration in milliseconds
(default: ~800 ms)

Defines how long the server waits through silence before ending a speech turn. This determines how tolerant the system is of natural mid-sentence pauses (such as thinking, breathing, or clause boundaries).

  • Recommended (500-800 ms): Provides a good balance—the model receives complete, contextually rich audio while keeping response latency reasonable.
  • Too low (below 200 ms): Ends speech turns during natural pauses, splitting utterances into small fragments that can degrade transcription and response quality.
  • Too high (above 2000 ms): Adds noticeable delay before the model begins responding.
Interruption behavior (activityHandling)
activityHandling
  • INTERRUPT (default)
  • NO_INTERRUPT

Defines how the server handles incoming user activity while generating a response:

  • INTERRUPT: Immediately cancels the model's current response when user activity is detected.
  • NO_INTERRUPT: Continues generating the response without interruption.
Turn context coverage (turnCoverage)
turnCoverage
  • ONLY_ACTIVITY (default)
  • ALL_INPUT
  • AUDIO_ACTIVITY_AND_ALL_VIDEO

Defines what streamed input is included in the conversational turn context:

  • ONLY_ACTIVITY: Excludes silence, retaining only segments where user activity was detected.
  • ALL_INPUT: Retains all streamed input, including audio silence.
  • AUDIO_ACTIVITY_AND_ALL_VIDEO: Retains all streamed video frames, but only audio segments where activity was detected.

Handle interruptions

If the server detects incoming user speech while the model is generating a response and activityHandling is set to INTERRUPT (the default), be aware of the following behaviors:

  • Generation is canceled: The model immediately halts its response and discards any pending tool calls.

  • Session history is truncated: Only the content already transmitted to your app before the interruption is preserved in the session context window.

  • An interruption signal is emitted: The server sends a response message indicating that generation was interrupted (such as wasInterrupted in Swift or interrupted in Kotlin, Java, Web, Flutter, and Unity).

Important: If your app buffers streamed audio for real-time playback, check for the interruption signal in your response listener. If an interruption signal is detected, your app should immediately stop audio playback and clear any queued audio buffers so the user doesn't hear stale audio overlapping with the model's new turn.

Disable automatic voice activity detection (VAD)

To take complete manual control over conversational turns (such as for a push-to-talk interface), you can disable automatic voice activity detection (VAD) instead of configuring sensitivity parameters.

When automatic detection is disabled, the server won't automatically detect speech or trigger responses based on audio silence. Instead, your app must manually signal user activity boundaries during the active session.

2. Manually signal user activity boundaries

If you disable VAD, your app must manually demarcate the boundaries of each user activity turn:

  1. Signal activity start: Call sendStartActivityRealtime before sending audio data (for example, when a user presses a push-to-talk button).

  2. Stream user input: Continuously stream audio (or video) data using sendAudioRealtime.

  3. Signal activity end: Call sendStopActivityRealtime when the user finishes speaking (for example, when the user releases the push-to-talk button). This signals the end of the user's turn and triggers the model's response.

Note: When automatic VAD is disabled, the server acts immediately on sendStopActivityRealtime with no additional wait or silence tolerance. If you use an automated client-side voice detector instead of a physical push-to-talk button, ensure your detector uses a silence threshold of at least 500 ms before calling sendStopActivityRealtime to avoid cutting off speech during natural pauses.

Swift

// If you disable automatic voice activity detection (VAD), you need to manually demarcate user activity.

// Signal the start of user activity (for example, on push-to-talk button press).
await session.sendStartActivityRealtime()

// Stream user audio data while the user speaks.
await session.sendAudioRealtime(audioData)

// Signal the end of user activity (for example, on button release) to trigger model response.
await session.sendStopActivityRealtime()
