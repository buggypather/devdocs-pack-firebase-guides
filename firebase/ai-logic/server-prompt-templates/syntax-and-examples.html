Template format, syntax, and examples

Preview: Using server prompt templates is a feature that's in Preview, which means that it isn't subject to any SLA or deprecation policy and could change in backwards-incompatible ways.


For Firebase AI Logic, the Firebase console provides a guided UI for you to specify the contents of a template.

Server prompt templates use a Dotprompt-based syntax and format. On this page, you can find detailed descriptions of the template format and syntax, along with examples.

Here are the most important components for an example request to a Gemini model:

---
model: 'gemini-3.8-flash'
---

{{role "system"}}
All output must be a clearly structured invoice document.
Use a tabular or clearly delineated list format for line items.

{{role "user"}}
Create an example customer invoice for a customer named {{customerName}}.

  • The top section within the triple-dashes contains the model name as well as optionally any model configuration, input validation, or schema you want to send in the request. It's written as key-value pairs and is commonly called YAML frontmatter.

  • The body of the template contains the prompt. It can also optionally include system instructions and input values (using Handlebars syntax).

Important: Make sure to review the list of not-yet-supported features for the initial release of server prompt templates.


This page provides detailed descriptions of the template format and syntax, along with examples, for the following:

  • Hello world

  • Model configuration

  • Thinking configuration

  • Safety settings

  • System instructions

  • Input variables

  • Control flows (loops & conditionals)

  • Input validation and schema

  • Output schema

  • Multimodal input (images, videos, audio, PDFs, etc.)

  • Tool use (function calling, code execution, URL context, Grounding with Google Search, Grounding with Google Maps)

All the examples on this page show templates that use gemini-3.8-flash, but you can use any Gemini model supported by Firebase AI Logic (except for Gemini Live API models).

Control generation of responses

You can control the generation of responses in a variety of ways depending on your use case and the level of control that you need.

Model configuration

Set a model configuration to control how the model generates a response, like max output tokens, stop sequences, etc.

Configuration (frontmatter)

---
model: 'gemini-3.8-flash'
config:
  maxOutputTokens: 200
  stopSequences: ["red"]
---

Prompt and (as applicable) system instructions

Write a story about a magic backpack.


Thinking configuration

Specify a thinking-related configuration for models that support thinking.

Note: The Gemini 2.5 models use thinking budget instead of thinking level, and the Gemini 3.x models support thinking budget for backwards-compatibility. However, the Gemini 4.x models do not support thinking budget (and will return a 400 error if it's set). Also, if you set both thinkingLevel and thinkingBudget in the same config, the request returns an error.

Configuration (frontmatter)

  • Gemini 3.x and later models (thinking levels)

    ---
model: 'gemini-3.8-flash'
config:
  thinkingConfig:
    thinkingLevel: medium
    includeThoughts: true
---

  • Gemini 2.5 models (thinking budgets)

    ---
model: 'gemini-2.5-flash'
config:
  thinkingConfig:
    thinkingBudget: 1024
    includeThoughts: true
---

Prompt and (as applicable) system instructions

Solve x^2 + 4x + 4 = 0


Safety settings

Use safety settings to adjust the likelihood of getting responses that may be considered harmful.

Configuration (frontmatter)

Example with one safety setting:

---
model: 'gemini-3.8-flash'
config:
  safetySettings:
    - category: HARM_CATEGORY_HARASSMENT
      threshold: BLOCK_ONLY_HIGH
---

Example with multiple safety settings:

---
model: 'gemini-3.8-flash'
config:
  safetySettings:
    - category: HARM_CATEGORY_HARASSMENT
      threshold: BLOCK_ONLY_HIGH
    - category: HARM_CATEGORY_HATE_SPEECH
      threshold: BLOCK_MEDIUM_AND_ABOVE
---

Prompt and (as applicable) system instructions

Write a story about a magic backpack.


System instructions

Set system instructions to steer the behavior of the model. You include them as part of the prompt:

  • Specify the system instructions using the {{role "system"}} syntax.

  • Specify the text prompt using the {{role "user"}} syntax.

Configuration (frontmatter)

---
model: 'gemini-3.8-flash'
---

Prompt and (as applicable) system instructions

{{role "system"}}
All output must be a clearly structured invoice document.
Use a tabular or clearly delineated list format for line items.

{{role "user"}}
Create an example customer invoice for a customer.


Input variables

Some prompts are static, but you often need to include some data from the user as part of the prompt.

You can include dynamic input variables in the prompt using Handlebars expressions, which are contained within {{ }} tags in the format of {{variableName}} or {{object.propertyName}} (for example, Hello, {{name}} from {{address.city}}).

Important: Always provide input validation to ensure that the data passed in the request matches your expectations. Note that if you use an input variable in your prompt and you provide input validation schema, then that value is considered required (unless you denote it as optional in the schema).

Configuration (frontmatter)

---
model: 'gemini-3.8-flash'
---

Prompt and (as applicable) system instructions

Create an example customer invoice for a customer named {{customerName}}.

You can provide a default value in the template, but the value of an input variable is usually provided by the client as part of the request.

Control flows (loops & conditionals)

To write more complex prompts, you can use conditional blocks (like #if , else, and #unless) and iteration (#each).

You can provide additional contextual information as variables with a special @ prefix:

  • @first: true when iterating the first item of an #each block.
  • @last: true when iterating the last item of an #each block.
  • @index: gives the (zero-based) index position of the current element.

See the Handlebars documentation for information on all of the built-in logical helpers.

Configuration (frontmatter)

---
model: 'gemini-3.8-flash'
---

Prompt and (as applicable) system instructions

Create an example customer invoice for a customer named {{customerName}}.

Include entries for each of the following products

{{#each productNames}}
  {{#if @first}}
  Include line items for the following purchases
  {{/if}}
  - {{this}}
{{/each}}

{{#if isVipCustomer}}
Give the customer a 5% discount.
{{/if}}

Note that conditionals only accept a variable reference, not any type of expression, for example:

  • The following works: {{#if isVipCustomer}} ... {{/if}}
  • The following does not work: {{#if customer.type == 'vip'}} ... {{/if}}

If the variable is a boolean, then the conditional works as you would expect. If the variable is not a boolean then the conditional is effectively an "is-not-null" check. This can be useful for handling optional inputs, for example:

{{#if customerName}}
Hello {{customerName}}
{{else}}
Hello Guest
{{/if}}


Input validation and schema

If you have data coming from the client, we strongly recommend using input schema to help protect against prompt injection as well as ensure that the data passed in the request matches your expectations.

  • You can provide default values in case the client doesn't provide a value.

  • The schema supports scalar types string, integer, number, boolean, and object. Objects, arrays, and enums are denoted by a parenthetical after the field name.

  • All properties are considered required unless you denote it as optional with ?. When a property is marked as optional, it's also made nullable to provide more leniency for LLMs to return null instead of omitting a field.

Note: If you specify an input schema and the client fails to pass valid inputs with a request, then the request will be rejected with a 400 error.

Here's a basic example for providing input schema. You can find a more advanced schema just below.

Configuration (frontmatter)

---
model: 'gemini-3.8-flash'
input:
  default:
    isVipCustomer: false
  schema:
    customerName: string, the customers name  # string, number, and boolean types are defined like this
    productNames?(array, list of products to include in the invoice): string  # optional fields are marked with a ?
    isVipCustomer?: boolean, whether or not the customer is a VIP
---

Prompt and (as applicable) system instructions

Create an example customer invoice for a customer named {{customerName}}.

Include entries for each of the following products

{{#each productNames}}
  {{#if @first}}
  Include line items for the following purchases
  {{/if}}
  - {{this}}
{{/each}}

{{#if isVipCustomer}}
Give the customer a 5% discount.
{{/if}}

View a more complex example for providing input schema

Configuration (frontmatter)

---
model: gemini-3.8-flash
input:
  schema:
    customer:
      type: object
      description: details about the customer
      required: [lastName, address]
      properties:
        firstName:
          type: string
          minLength: 2
          maxLength: 50
        lastName:
          type: string
          minLength: 2
          maxLength: 50
        address:
          type: object
          description: customer's address
          required: [street, city, country]
          properties:
            street:
              type: string
            city:
              type: string
            country:
              type: string
        isVip:
          type: boolean
          description: whether or not the customer is a VIP
    purchases?:
      type: array
      description: list of things the customer purchased
      items:
        type: object
        required: [itemName, sku, cost, quantity]
        properties:
          itemName:
            type: string
          sku:
            type: string
            minLength: 7
            maxLength: 19
            pattern: "^[0-9]{1,3}-[a-zA-Z]{3,10}-[0-9]{1,4}$"
          category:
            enum: ["ELECTRONICS", "APPAREL", "HOME", "MISC" ]
          cost:
            type: number
            minimum: 0
          quantity:
            type: number
            minimum: 1
            maximum: 200
---

Create an example customer invoice for a customer.

The customer's address is

{{customer.firstName}} {{customer.lastName}}
{{customer.address.street}}
{{customer.address.city}}
{{customer.address.country}}

{{#each purchases}}
  {{#if @first}}
  Include line items for the following purchaes
  {{/if}}
  - {{quantity}} x {{itemName}} ({{sku}}) @ ${{cost}}, category {{category}}
{{/each}}

Give the customer a 5% discount.
{{/if}}


Output schema

If you want the model to generate structured JSON output, then you can specify an output schema. By specifying format: json, you're constraining the model to always return a JSON response that follows the specified schema.

  • The schema supports scalar types string, integer, number, boolean, and object. Objects, arrays, and enums are denoted by a parenthetical after the field name.

  • All properties are considered required unless you denote it as optional with ?. When a property is marked as optional, it's also made nullable to provide more leniency for LLMs to return null instead of omitting a field.

Note: Server prompt templates do not yet support constraining the output to a list of enums.

Here's a basic example for generating structured JSON output. You can find a more advanced schema just below.

Configuration (frontmatter)

---
model: gemini-3.8-flash
output:
  format: json
  schema:
    invoiceId: string
    invoiceFile(object, an invoice file):
      url?: string
      contents: string
      mimeType: string
---

Prompt and (as applicable) system instructions

Create an example customer invoice.

View a more complex example for generating structured JSON output

Configuration (frontmatter)

---
model: gemini-3.8-flash
output:
  format: json
  schema:
    title: string  # string, number, and boolean types are defined like this
    subtitle?: string  # optional fields are marked with a ?
    draft?: boolean, true when in draft state
    status?(enum, approval status): [PENDING, APPROVED]
    date: string, the date of publication for example '2024-04-09' # descriptions follow a comma
    tags(array, relevant tags for article): string  # arrays are denoted via parentheses
    authors(array):
      name: string
      email?: string
    metadata?(object): # objects are also denoted via parentheses
      updatedAt?: string, ISO timestamp of last update
      approvedBy?: integer, id of approver
    extra?: any, arbitrary extra data
    (*): string, wildcard field
---

Prompt and (as applicable) system instructions

Store all the specified information about the provided article.


Multimodal input

Multimodal prompts sent to a Gemini model can include multiple types of input, including files (like text along with images, PDFs, plain-text files, audio, and video).

  • Provide a file using its URL with the {{media url}} syntax.

  • Provide an inline file with the {{media type="mime_type" data="contents"}} syntax.

Tool use

Server prompt templates support the following tools.

  • Function calling

  • Code execution

  • URL context

  • Grounding with Google Search

  • Grounding with Google Maps

If you want your users to provide any additional information for the request to the model, then use input variables within the server prompt template, along with input validation.

Important: During initialization of the model in your client code, do not list the tools that the model has access to. Instead, tools must be listed in the tools object of the template's frontmatter.

Function calling

See the complete guide for function calling using server prompt templates.

Code execution

The code execution tool enables the model to generate and run Python code.

Configuration (frontmatter)

---
model: 'gemini-3.8-flash'
tools:
  - codeExecution
---

Prompt and (as applicable) system instructions

What is the sum of the first 50 prime numbers?
Generate and run code for the calculation, and make sure you get all 50.

URL context

The URL context tool lets you provide additional context to the model in the form of URLs. This example also shows how you might specify input validation for URLs if they're provided by the user.

Configuration (frontmatter)

---
model: 'gemini-3.8-flash'
input:
  schema:
    url1:
      type: string
      pattern: '^https?://[\w.-]+\.[a-z]{2,}\S*$'
      maxLength: 100
    url2:
      type: string
      pattern: '^https?://[\w.-]+\.[a-z]{2,}\S*$'
      maxLength: 100
tools:
  - urlContext
---

Prompt and (as applicable) system instructions

Compare the ingredients and cooking times from the recipes at {{url1}} and {{url2}}

Grounding with Google Search

The Grounding with Google Search tool connects the model to real-time, publicly-available web content.

Important: If a response contains "Google Search suggestions" (the searchEntryPoint field within the groundingMetadata object), then that response is a "grounded result" so you're required to comply with the "Grounding with Google Search" usage requirements, which includes how you display the result. Learn how to use and display a grounded result.

Configuration (frontmatter)

---
model: 'gemini-3.8-flash'
tools:
  - googleSearch
---

Prompt and (as applicable) system instructions

Who won the Euro 2024?

Grounding with Google Maps

The Grounding with Google Maps tool provides the model with geospatial data for location-aware functionality.

Important: If a response contains a groundingMetadata object (meaning the response is a Google Maps Grounded Result), you're required to comply with the Grounding with Google Maps usage requirements, which includes how you display the result. Learn how to meet service usage requirements.

To use the googleMaps tool, list it in the tools object of the template's frontmatter. The example below shows some additional optional configurations:

  • Allow input variables from the client-side code, and perform input validation and schema of that input (in this example, a question).

  • Configure the googleMaps tool by providing a location's coordinates and/or a language code in your client-side code using a TemplateToolConfig.

Below the example template, find an expandable that shows client-side code samples for working with these optional configurations.

Configuration (frontmatter)

---
model: 'gemini-3.8-flash'
tools:
  - googleMaps
input:
  schema:
    question: string
---

Prompt and (as applicable) system instructions

{{role "system"}}
You are a helpful tour guide. Use the Google Maps tool with the provided coordinates to answer the user's question based on their location.

{{role "user"}}
{{question}}

View client-side request that shows working with optional configurations of the googleMaps tool when using a template

Swift

import CoreLocation
import FirebaseAILogic

// Initialize the Gemini Developer API backend service.
let ai = FirebaseAI.firebaseAI(backend: .googleAI())

// Example: Coordinates for New York City
let latAndLong = CLLocationCoordinate2D(latitude: 40.7128, longitude: -74.0060)

// (Optional) Define a RetrievalConfig to configure the Grounding with Google Maps tool.
// You can optionally provide a location's coordinates and/or a language code
// for more relevant and personalized Google Maps results.
let retrievalConfig = RetrievalConfig(
    location: latAndLong,
    // Example: Language code for English (US)
    languageCode: "en-US"
)

// Wrap the RetrievalConfig inside a TemplateToolConfig.
let templateToolConfig = TemplateToolConfig(retrievalConfig: retrievalConfig)

// Create a `TemplateGenerativeModel` instance.
let model = ai.templateGenerativeModel(
    // Pass the template-compatible tool configuration.
    toolConfig: templateToolConfig
)

do {
    // Generate content using your server template ID, inputs, and grounding configuration.
    let response = try await model.generateContent(
        // Specify a template ID that uses the Google Maps tool.
        templateID: "TEMPLATE_ID",
        // Provide the values for any input variables required by your template.
        inputs: [
            "question": "restaurants near me?"
        ]
    )

    print(response.text ?? "No text in response.")
} catch {
    print("An error occurred: \(error)")
}

// Make sure to comply with the "Grounding with Google Maps" usage requirements
